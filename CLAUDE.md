## Engineering rules

- No direct edits/commits to `main`. Every scoped task goes through an issue, dedicated feature branch and pull request. **Never merge automatically.**
- Inspect real source and tests; don't trust previous AI summaries. Test in a clean environment if possible. Be explicit about commands, outputs and what wasn't run.
- Write the smallest, simplest, scientifically defensible code using Python and PyTorch. Explain tensor shapes, convolutions, pooling, skip connections, loss and backprop in plain language for a university student.
- Do not build dashboards, mobile apps, diabetes classifiers or huge models before a real U-Net baseline trains on real FIVES labels.
- Never silently spend money, deploy, publish, send messages, download or upload identifiable patient data, edit the upstream repo, or modify production systems. Seek approval for actions not within the assigned scope. Ask before adding expensive GPU services or importing restricted third-party weights.
- No images, masks, datasets, personal records, credentials, large checkpoints or models in Git. Use external datasets and `.gitignore`.
- FIVES: preserve official 600 train/200 test split; create validation only from training images; inspect for patient-level overlaps (800 images from 573 patients). If subject IDs cannot be recovered, disclose uncertainty rather than asserting independence.
- Image interpolation can be bilinear; **mask resizing must be nearest-neighbor**. Validate binary labels, paired filenames, orientation and alignment. Keep red/green/blue order consistent and document all preprocessing. Test with small fake image/mask fixtures but label fixtures as synthetic.
- For first losses, use `BCEWithLogitsLoss`; raw U-Net output is logits. Sigmoid probabilities are for inference/metrics. Use validation-only threshold selection and never tune on the official test split.
- Do not fabricate training loss, model metrics, medical usefulness or external adoption. Segmenter Dice, geometry centerline error, measurement reproducibility, and clinical utility are separate claims.
- Distances/widths in **pixels only**, unless a validated scale conversion exists. No clinical blood-pressure estimation or diagnosis from retinal images; Yusufu 2025 concerns associations, Poplin 2018 predicts from whole photographs and is not evidence MedSkel can do that.

## Existing upstream evidence — preserve the trade-off

The original `medskel` repo reports CHASE inter-observer relative vessel-length movement about **3.2%** for MedSkel vs **9.3%** for thinning, but positional centerline agreement **71.6%** MedSkel vs **80.9%** thinning (worse), and approximately **66×** slower on one retinal example. These results are not clinical or anatomical ground-truth accuracy. CHASE 28 images come from 14 children; account for paired eyes in future statistical analyses. The MedSkel bisector/wavefront implementation is partially incomplete for split events. No claim that our new CNN already improves these results is justified.
